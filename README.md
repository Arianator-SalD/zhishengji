# 职升机 Careerfly

> 帮助大学生了解自己、看清岗位，并把职业选择变成下一步行动。

职升机是一个面向大学生的职业决策与求职规划平台。我们希望把真实学长学姐和一线从业者的经验整理成可以持续追问的**专家数字分身**，让用户结合自己的背景讨论职业困惑，再通过职业画像和行动计划持续推进求职准备。

本仓库是产品的 Web Demo，展示“职业探索 → 专家咨询 → 行动与复盘”的使用过程。目前重点接入了 **Sally 的文字与语音咨询**，其余模块用于演示产品流程。产品定位与规划依据 [团队 PRD](https://my.feishu.cn/docx/TxtqdvKn9oTP2kxF1zVcUReUnFe)，具体实现范围见下文。

## 我们想解决什么问题

求职方向探索期的大学生，往往需要回答三个相互关联的问题：

- **我适合做什么？** 对兴趣、能力和职业偏好的认识还不清楚，很难判断哪些方向值得尝试。
- **这个岗位实际在做什么？** 招聘描述和零散经验难以还原真实工作，需要有相关经历的人解释岗位要求、工作日常和选择背后的取舍。
- **想清楚以后，下一步怎么做？** 知道一个方向之后，还需要把目标拆成任务，通过实践结果不断调整。

因此，产品把低门槛的职业成长工具与专家数字分身咨询放在一起：前者帮助用户积累自我认知和行动记录，后者在关键选择时提供更有针对性的职业讨论。

## 这个网页里可以做什么

下面介绍各页面在产品中的作用；其中部分能力仍处于原型阶段。

| 页面 / 模块 | 用户来这里做什么 | 在职业规划中的作用 |
| --- | --- | --- |
| 职业画像 | 通过问卷梳理工作风格、职业偏好、优势和目标方向 | 建立个人 Career Profile，为后续咨询提供背景 |
| 专家分身 | 按方向或问题类型筛选专家，查看经历、擅长领域和推荐问题 | 帮助用户找到适合讨论当前困惑的经验来源 |
| AI Chat / 语音咨询 | 讲述自己的情况，向专家数字分身提问并继续追问 | 围绕职业方向、岗位认知、人岗适配和求职路径展开讨论 |
| 我的行动计划 | 查看阶段任务、勾选完成状态、跟踪进度 | 把咨询得到的建议落实到求职准备中 |
| 咨询记录 | 回看咨询结论、关键建议和下一步行动 | 让一次咨询能在后续准备中继续发挥作用 |
| 社区与收藏 | 浏览经验与问题，体验讨论、悬赏问答和收藏流程 | 补充同路人的案例与经验，支持持续探索 |

其中，**专家数字分身**指的是基于某位专家的经历、知识、判断方式和表达习惯提供咨询的 AI。产品希望让专家经验可以被更多人随时调用，并通过追问适配不同用户的具体处境。

当前 Sally 的实现方式是把整理好的个人资料和参考问答提供给模型，结合本次对话生成回答；尚未实现独立模型训练或完整的专家知识管理平台。

## 一次典型的使用过程

以一位正在考虑产品经理方向的同学为例，产品希望支持这样的过程：

1. **梳理自己**：完成职业探索问卷，明确已有经历、偏好以及还不确定的地方。已有明确问题的用户也可以直接进入咨询。
2. **找到合适的专家**：浏览产品、招聘等方向的专家资料，选择与当前问题匹配的数字分身。
3. **带着背景提问**：“我没有技术背景，应该尝试产品经理吗？”继续追问岗位要求，以及自己的经历能支持什么判断。
4. **明确下一步**：把讨论转成可验证的行动，例如分析目标岗位 JD、梳理一段项目经历、完成一次岗位相关实践。
5. **执行并复盘**：记录完成情况和新发现，更新职业画像，再带着更具体的问题咨询。

这个过程对应 PRD 的核心闭环：**免费探索 → 持续记录 → 关键问题咨询 → 行动建议 → 执行反馈 → 更新画像**。完整闭环仍是产品建设目标，当前 Demo 尚未将这些数据自动串联。

## 当前 Demo 实现到哪一步

| 能力 | 当前实现 |

| 专家浏览与筛选 | 可浏览专家卡片、详情与推荐问题；其他专家资料为演示内容，不代表已入驻 |
| Sally 文字咨询 | 已接入真实后端，配置有效模型凭证后支持流式回答和多轮追问 |

真实咨询目前仅保留当前连接的近期上下文，断线或开启新会话后清空，尚未实现跨会话的长期职业记忆。语音依赖服务商权限、额度和音色配置；本次 README 更新核对了代码，未重新执行真实服务验收。

## 产品规划与商业模式

按照 PRD，首期产品聚焦三项能力：**Career Profile、游戏化职业探索、付费专家数字分身咨询**。

- **免费成长工具**：通过问卷、探索任务、阶段进度和路径记录，帮助用户持续了解自己，并积累咨询所需的背景。
- **付费专家咨询**：围绕职业方向选择、真实岗位认知和个性化路径规划，提供有明确专家经验来源的咨询服务。
- **后续衔接**：让咨询建议进入行动计划，让执行反馈更新画像，并逐步完善专家经验录入、更新和知识边界管理。

付费咨询是规划中的核心商业化场景，具体定价和收费规则尚未定稿，当前 Demo 未接入真实交易。

## 技术实现

前端使用 HTML、CSS 和 JavaScript，FastAPI 提供页面服务与 WebSocket 对话接口。

- **文字链路**：用户输入 → FastAPI → DeepSeek 流式回答 → 页面逐步显示。
- **语音链路**：浏览器麦克风 → 火山流式语音识别 2.0 → DeepSeek 流式回答 → 火山语音合成 2.0 → 浏览器分段播放。
- **专家资料**：从本地人格资料与参考问答构建模型上下文，当前无需向量数据库。

| 目录 / 文件 | 用途 |
| --- | --- |
| `static/` | 实际服务的网页、文字与语音交互、行动计划脚本 |
| `server/` | FastAPI 服务、访问保护、供应商接入与会话管理 |
| `content/` | Sally 的人格资料、参考问答及开发用模拟用户画像 |
| `prototype/` | 原始 HTML 交互原型 |
| `tests/` | 后端、音频和浏览器交互验证 |

项目改动与验证记录见 [迭代日志](迭代日志.md)，Render 配置见 [部署步骤](RENDER部署.md)。

## 启动

在本文件所在目录运行：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m uvicorn server.main:app --host 127.0.0.1 --port 8765
```

打开 http://127.0.0.1:8765 ，点击Sally卡片。不要直接双击 HTML，页面需要同源后端。

本机已有 `.venv` 时，可直接双击 `启动本地Demo.command`。它只监听本机地址。

## 你需要提供的配置

在项目 `.env` 中填入，保存后重启后端。不要把密钥放进 HTML 或聊天消息。

部署到 Render 时，在 Environment 页面配置密钥，并设置至少 12 位的 `DEMO_ACCESS_PASSWORD`，供团队成员进入演示使用。它是共享演示口令，不是模型 Key；Render 环境缺少访问口令时，除健康检查外默认不开放页面和对话。

| 本地字段 | 从哪里获得 |
| --- | --- |
| `LLM_API_KEY` | [DeepSeek 开放平台](https://platform.deepseek.com/)创建 API Key；需要可用 API 余额 |
| `LLM_MODEL` | 默认 `deepseek-flash`，可以换成账户可调用的模型 ID |
| `VOLC_ASR_API_KEY` | [火山语音控制台](https://console.volcengine.com/speech/app)中对流式识别服务有权限的 API Key |
| `VOLC_TTS_API_KEY` | 对语音合成服务有权限的 API Key；若同一 Key 获得两项权限，可填相同值 |
| `VOLC_TTS_SPEAKER` | 控制台音色详情对应的 ID。示例为 `zh_female_vv_uranus_bigtts`，需确认该账户可用 |

语音识别、语音合成与 DeepSeek 分别计费，语音试用额度不包含模型费用。资源实例名称不是 API Key，也不应替换配置里的资源类型 ID。旧版语音控制台也可分别填写 App ID + Access Token；新版 Key 优先。

页面显示“已配置”仅表示本地配置齐全；权限、额度、音色是否匹配，需要真实请求验证。未配置时会显示提示，不生成模拟实时回答。

## 演示方式

1. 从 Sally 专家页面的四个推荐问题开始，覆盖转行、技术深度、产品方案、经历主线；参考回答保存在 `content/qa.json`。
2. 配好 DeepSeek 后，用 AI Chat 测试四个问题和各自一条追问。此入口只输出文字，便于先验证内容。
3. 配好两项语音服务，打开“语音通话”，点“开始说话”。说完后点“说完了，发送”，短暂停顿不会自动提交。每轮最长 60 秒。
4. 回答按句合成并连续播放。点“停止回答”再继续提问。第一版采用明确开始/停止操作，尚未实现边播放边监听的自动插话。
5. 当前页面默认从零开始，不带模拟画像；聊天弹窗内点“新会话”会清空上下文。后端保留模拟画像数据供开发测试。

## 内容与记忆

- `content/persona.md`：本人经历、判断方式、口语表达规则；资料里的内容作为参考，不能覆盖系统指令。
- `content/qa.json`：四组问题、参考回答、追问与原文来源；Photo Coach 明确是产品构想。
- `content/demo_user.json`：模拟同学的已知背景、待验证偏好和未知信息，区别于咨询者本人经历。
- 每个 WebSocket 单独保留近期消息，最多 24 条；断线即清空，不持久化、不写日志。语音回答只把浏览器确认播完的句子计入后续上下文，打断时当前未播完句子不计入。

飞书精选内容已整理为本地文件，第一版不需要注册飞书应用，也不需要向量数据库。更新资料时改这三个文件并重启即可。

## 检查与部署

```sh
.venv/bin/python -m pytest tests -q
node --test tests/audio-worklet.test.cjs
```

自动化用注入的测试替身检验协议、流式处理、会话隔离与打断，不代表真实服务验收。真实验收需要实际说话，检查识别准确性、回答内容、播音衔接和两轮追问。

团队对外演示时，可将同一 FastAPI 进程部署到支持长期 WebSocket 的服务器，域名走 HTTPS（麦克风需要安全上下文，本机 localhost 例外），代理开启 WebSocket 升级并设置足够超时。Render 域名会自动加入允许主机，其他域名需设置 `ALLOWED_HOSTS`。已提供共享演示口令、每个 IP 每分钟最多 5 次登录尝试、单进程最多 3 个同时连接；口令有效期 12 小时，修改口令会使旧登录失效。已登录用户仍能消耗额度，服务商侧应设置费用提醒或预算。本版本适用于受邀团队演示，不是多租户商业服务。

接口：`GET /health`、`GET /api/config`、`WS /ws/voice`。ASR 上传 PCM16k 单声道；TTS 返回 PCM24k，由 AudioContext 顺序调度。

官方协议参考：[DeepSeek API](https://api-docs.deepseek.com/)、[火山流式识别](https://docs.volcengine.com/docs/6561/1354869?lang=zh)、[火山流式合成](https://docs.volcengine.com/docs/6561/1598757?lang=zh)。
