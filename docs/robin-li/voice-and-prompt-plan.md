## 先看结论

建议采用 **公开访谈式交流 + 云舟 2.0 预置男声**。人物表达强调平实、直接、讲原因、看实际效果；声音以自然交流、长时间听不累为目标。云舟是本轮优先试听候选，尚未完成听感确认，不声称接近李彦宏本人的声音。

完整系统提示词见 [角色 Prompt 评审稿](role-prompt-review.md)。原资料见 [公开讲话与访谈整理](public-remarks.md)。这两份文件用途不同：Prompt 规定如何交流，资料提供有时间和场合的事实与观点。

## 表达设计

本轮重点核对了第一财经 2024 年 7 月 6 日公开的李彦宏、杨宇东、陈茜对话。访谈中能看到他直接回应问题、举应用例子、区分场景要求，以及说明探索过程和判断限制的表达方式。将这些特征用于大学生咨询，是本项目的设计推断，不是对其真实私人谈话风格的复刻。[第一财经访谈](https://www.yicai.com/news/102180527.html)

比较了三个方向：大会演讲式表达适合开场介绍，但容易显得距离远；通用职业顾问式表达亲切，却不容易体现人物特点；访谈式交流既保留判断与解释，也适合连续追问。因此采用第三种。

Prompt 的具体处理：

- 先回应眼前问题，再解释主要原因，必要时才举例或追问。
- 关注具体用户、使用效果、成本和现实限制，不把每个问题都转成创业或做 AI 产品。
- 允许不同意和修正判断，不输出总裁腔、成功学或固定夸奖。
- 普通问题约 100—180 字；简单追问更短，用户要求细讲时再展开。
- 公开观点、人物事实和本轮生成的建议分开处理，不编造亲历和内部信息。
- 正文适合逐句播报，不让标题、表格、舞台提示和控制参数进入语音。

文件附有 8 组原创示例，用于评审表达而非充当李彦宏原话。角色身份在页面说明即可，正常回答不反复自我声明；直接询问身份时明确说明。

## 豆包音色选型

本轮通过真实浏览器读取火山引擎动态音色列表，确认以下两项列在豆包语音合成模型 2.0 音色表内，均为通用场景中文音色，支持指令遵循。[官方音色列表](https://www.volcengine.com/docs/6561/1257544?lang=zh)

| 顺位 | 官方音色名称 | voice_type / 请求中的 speaker | 选择依据 |
| --- | --- | --- | --- |
| 优先试听 | 云舟 2.0 | `zh_male_m191_uranus_bigtts` | 官方将其列为通用场景音色，并列入 S2S 主打音色；适合作为对话用途的首个候选，最终以试听为准 |
| 对照试听 | 渊博小叔 2.0 | `zh_male_yuanboxiaoshu_uranus_bigtts` | 同为通用场景、同模型版本的男声候选，用于比较咨询场景中的成熟感与自然度；名称不能代替听感评估 |

注意选用表中的 `uranus` 版本。列表也包含渊博小叔旧版的 `moon` ID，不应混用。

优先使用现有 v3 SSE 链路，候选资源 ID 为 `seed-tts-2.0`，保留 24000 Hz、单声道 PCM 播放方式。当前 `server/providers.py` 已使用这套请求结构；本轮没有修改配置或服务代码。

后续为李彦宏单独选择以下请求内容，身份与音色按专家配置，不能直接替换 Sally 使用的全局环境变量：

```json
{
  "req_params": {
    "text": "待播报的回答正文",
    "speaker": "zh_male_m191_uranus_bigtts",
    "audio_params": {
      "format": "pcm",
      "sample_rate": 24000
    }
  }
}
```

以上只展示与音色有关的请求片段；鉴权、用户字段和响应处理继续使用后端已有实现。首轮先保持默认语速和音量，听过之后再决定是否调整，不额外引入未经核对的情绪参数。LLM 的角色提示词不会自动变成 TTS 的语气指令。

## 试听与确认

在 [火山引擎豆包语音体验页](https://www.volcengine.com/products/Audio-editing-and-sound-processing) 选择“云舟 2.0”试听；页面若要求登录，使用已有账号进入官方控制台。渊博小叔 2.0 可在官方音色列表所指向的在线音色体验中查找。

建议两种音色朗读相同文本，避免内容不同干扰选择。以下为原创角色示例，并非李彦宏原话：

> 这是职升机 AI 分身的合成音色试听。我觉得，判断一个方向值不值得做，可以先看看它解决了什么具体问题。比如你做了一个帮助同学整理课程资料的工具，就找人实际用一用，看看哪些地方省了时间，哪些回答还不可靠。这个结果，比演示的时候看起来有多聪明，更能说明问题。

试听时重点听：是否像正常交谈；年龄感是否适合人物形象；长句停顿是否自然；技术词和问句是否清楚；连续听几轮是否舒适。不以“与本人一模一样”作为验收标准。

本轮尝试准备两份本地试听，但检查发现 `Settings.from_env()` 未获得可用的 LLM 或 TTS 凭据，于发出请求前停止。因此没有生成音频，没有真实模型输出，也没有时延或音质测试结论。该检查只反映本地环境，不代表线上凭据或服务状态。

## 接入时需要处理的事项

用户确认后，下一轮再实施以下改动：

1. 建立李彦宏独立资料配置，将相关公开资料和精选 QA 加入上下文；本轮 Prompt 本身不会自动读取外层资料文件。
2. 增加专家 ID 路由，分别加载 Sally 与李彦宏的角色、资料和音色。当前 `server/context.py` 中“Sally 的说话方式”等专用指令也要按专家区分，避免两个角色同时生效。
3. 将李彦宏的文字与语音入口由 mock 切到真实链路，检查专家切换后的录音、回复、播放和历史隔离。
4. 以可用的服务凭据生成试听并验证模型回答；随后检查流式播报和打断。真实接口验证结果单独记录，不拿本轮静态检查代替。
