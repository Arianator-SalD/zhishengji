## 1. 项目是什么

**职升机 Careerfly 是面向大学生的职业决策与求职规划平台，以职业成长工具支持持续探索，以专家数字分身咨询帮助用户处理关键职业选择。**

项目处于商战方案与可体验产品原型的建设阶段。现阶段已有完整程度较高的网页交互原型，并为其中一个专家分身接入真实文字和语音服务；完整职业成长平台仍在逐步建设。

产品的长期价值在于：让用户更了解自己，获得有明确专家经验来源的岗位认知，并把咨询建议落实为行动。语音是咨询的一种交互方式，不能用单条语音接入链路概括整个项目。

## 2. 用户与问题

核心用户是**处于求职方向探索期、有学长学姐或行业专家咨询需求的大学生**。早期调研关注文商科学生的职业方向困惑；这是一条研究线索，不能据此把全部目标用户限定为某个专业或岗位。

| 用户问题 | 具体表现 | 产品希望提供的帮助 |
| --- | --- | --- |
| 自我认知不清楚 | 兴趣难以对应职业，对能力、偏好与价值排序缺少判断 | 通过探索与经历记录形成 Career Profile |
| 缺少真实岗位依据 | 看过招聘要求和经验分享，仍不了解日常工作与实际取舍 | 用一线从业者经验支持岗位认知与方向比较 |
| 建议缺少针对性 | 知道通用方法，却不知道自己的背景适用于哪条路径 | 通过补充背景和持续追问，讨论个性化问题 |
| 难以落实行动 | 不知道先准备什么，也缺少执行后的反馈 | 拆解阶段任务、记录结果并调整后续路径 |

预期交付是更明确的职业判断与下一步行动。当前没有证据支持录用保证、固定提效比例或已经验证的就业效果。

## 3. 产品结构与核心流程

### 免费职业成长工具

- **职业探索**：问卷、小游戏，识别兴趣、能力与职业偏好。
- **Career Profile**：沉淀基础背景、职业方向、目标和路径记录。
- **游戏化成长**：探索任务、求职闯关、积分或阶段进度、行动反馈。
- **路径记录**：保存探索经历与任务结果，持续更新个人职业画像。

这些工具承担低门槛进入、持续使用和背景积累的作用。

### 付费专家数字分身咨询

用户选择真实学长学姐或从业者对应的数字分身，围绕职业方向、真实岗位、人岗适配、求职路径和个性化困惑展开咨询。

分身的内容基础是专家的真实职业经历、岗位经验、行业知识、个人观点与决策逻辑。产品希望通过文字和语音交互，让这些经验能够被随时调用和反复追问。

### 核心闭环

**进入平台 → 可选职业探索 → 形成画像 → 免费任务与路径记录 → 遇到关键问题 → 选择专家分身 → 付费咨询 → 获得行动建议 → 执行反馈 → 更新画像。**

职业探索不是强制前置条件；已有明确问题的用户可以直接进入咨询。长期设计应让咨询、任务与画像互相衔接，当前代码尚未完整实现这条数据链路。

### 社区的角色

社区承担经验分享、同路人交流和结伴成长的作用。PRD 还提出通过真实案例和成长记录补充专家内容的方向。当前页面存在社区与悬赏问答原型；内容回流、知识更新和真实交易机制尚未形成完整服务。

## 4. 差异化与商业假设

PRD 提出的差异化方向有三项：

1. **经验有明确来源**：围绕真实专家的一手经历与判断组织咨询。
2. **咨询可持续追问**：结合用户背景讨论选择，降低专家经验获取的时间与成本门槛。
3. **成长持续积累**：让探索记录与执行反馈成为下一次咨询的背景。

这些是产品设计目标。不能把“完整复刻专家判断”“所有回答均可溯源”“已有多专家规模化供给”写成当前已验证能力。

服务模式规划为免费成长工具与付费专家咨询。具体价格、计费单位、分成、退款规则和机构合作方式仍需确定；PRD 中的按次收费、机构收费等讨论不等于已定稿方案。

推广规划涉及百度生态、校园渠道、小红书和知乎等。它们是拟探索的渠道，不代表已经获得平台合作、资源支持或完成投放。

PRD 包含市场规模、问卷比例、竞品价格及收入测算。本文未对这些数字做独立核验；后续用于路演或公开材料时，需要检查原始来源、时间、样本和假设，不能直接将测算当作经营结果。

## 5. 首期范围与待明确的问题

PRD 明确的 MVP 是：**基础 Career Profile、游戏化职业探索、付费专家数字分身咨询**。

PRD 的专家反馈还提出以下待解决问题：

- 用户背景中，哪些信息在首次进入时收集，哪些通过对话持续补充；客观经历和主观偏好如何区分。
- 专家经验如何录入、更新和校准，如何检查可靠性与覆盖范围。
- 数字分身在不擅长或无依据的问题上如何处理，何时需要真人介入。
- 职业规划与行动建议怎样才算有用，应该包含哪些内容。
- 首期是否聚焦某个岗位或学科，各阶段用什么可验证目标判断进展。
- 付费价值、价格与交付成本如何验证。

以上是待决策议题，不是已排期的工程任务。后续任务优先依据用户当次目标，避免把 PRD 中所有设想一次性扩展为实施范围。

## 6. 当前实现边界

本节结合迭代日志、已提交代码及本次会话的代码阅读整理。页面可见、代码接入、模拟测试通过和真实服务验收是不同状态。

| 模块 | 已有实现或记录 | 尚未具备或需要核实 |
| --- | --- | --- |
| 专家浏览 | 已恢复全部 10 位专家的详情访问与筛选交互 | 卡片中的演示履历不代表真实专家已入驻 |
| 真实咨询 | 当前真实后端咨询身份为 Sally，支持文字流式回答与语音链路 | 尚无完整多专家知识管理和服务体系 |
| 其他专家文字聊天 | 使用原型的示例对话与固定回复；按专家隔离本页消息和草稿 | 不调用真实模型；不能自动统一改成真实咨询身份 |
| 职业画像 | 有问卷、结果和进度展示 | 结果为预设演示；未实现真实个性化画像生成，也未自动注入真实咨询 |
| 行动计划 | 可勾选任务、同步进度，并在浏览器本地保存完成状态 | 任务仍为示例，未由真实咨询自动生成；没有跨账户同步证据 |
| 咨询记录 | 有预设记录、结论和行动建议展示 | 真实对话尚未自动归档到此页面 |
| 注册、账号、社区、收藏 | 有前端原型流程 | 尚无完整多用户后端、社区内容服务和支付系统 |
| 长期记忆 | 真实后端保留当前连接的近期对话 | 断线或新会话后清空，尚无跨会话职业记忆 |
| 专家供给与商业化 | 已提出产品方向 | 专家入驻、资料管理、持续校准、真实支付等仍待建设 |

当前专家实现采用本地人格资料、参考问答与通用模型上下文组合，并非独立模型训练。语音接入不意味着已经实现数字人视频形象。

工作区在本次整理时存在未提交的前端、原型和浏览器测试改动。它们不能自动视为 `main` 已提交成果或线上状态；接手任务先检查 Git 差异，不覆盖、不顺带提交其他协作者的工作。

## 7. 已形成的关键决策

以下决策来自迭代记录或用户明确要求；后续改动应理解其原因，避免无意回退。

| 决策 | 原因与后续约束 |
| --- | --- |
| 录音手动提交 | 曾出现短暂停顿截断表达；保留“开始说话 / 说完了，发送”，每轮最长 60 秒，不恢复短暂停顿自动提交 |
| 回答可停止 | 用户可停止播报后继续提问；尚未实现边播放边监听的自动插话 |
| 保留各专家身份与详情 | 曾因统一接入真实后端而影响其他专家入口；不因后端只有一个真实身份就禁用或替换其他专家页面 |
| 分离真实与模拟聊天 | 其他专家保留模拟回复；切换时停止正在进行的真实回答，防止消息和延迟事件串到其他对话 |
| 专家详情采用共同布局 | 已移除独立技术面板，保留统一专家介绍、推荐问题和咨询入口；新会话控制放在聊天弹窗 |
| 不默认加载模拟画像 | 真实咨询默认从零背景开始；不把开发用模拟用户经历说成当前用户经历 |
| 语音记忆以实际播放为准 | 仅将浏览器确认播完的句子纳入后续语音上下文，停止时未播完句子不计入 |
| 对外 README 只讲产品 | 用户明确要求基于 PRD 介绍产品；不加入 Sally、专家配置、密钥、部署细节或内部 PRD 链接 |

这些约定可由用户后续明确需求调整，本文不应成为阻止新需求的理由。
